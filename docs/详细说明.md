# 详细说明

README 只讲怎么用；这里讲实现细节、外接接口和排查。

## 工作流程

```
麦克风(VAD) → MediaRecorder → decodeAudioData → 16k WAV
        → POST /voice-tutor/stt
        → Whisper / 外接接口 / DSH 自带 SenseVoice
        → 文字进输入框（2 秒窗口）→ 自动或手动发送
        → 宿主监听 assistant/message → 合成语音排队
        → 前端轮询取音频播放 → 期间可被打断
```

宿主路由：`/voice-tutor/stt`、`/voice-tutor/correct`、`/voice-tutor/arm`、`/voice-tutor/audio`、
`/voice-tutor/voices`、`/voice-tutor/config`、`/voice-tutor/whisper-update`、
`/voice-tutor/whisper-update/check`、`/voice-tutor/whisper-update/apply`、`/voice-tutor/open`、
`/voice-tutor/debug`。

## 语音会话模式

用语音对话（点麦克风进入的录音会话，或语音通话专属会话）时，助手的回复会被朗读。为了让一轮
对话听起来自然，语音会话里的回复会被压成极短的一两句：不列清单、不复述前文，只保留能听懂的
核心信息。菜单、长代码块、表格也不适合直接念出来。

这是**会话级行为，不是插件 bug**：插件只负责把这段回复念出来，简短与否由当前会话模式决定。
如果是在打字讨论，这套规则会让回答显得过于省略——建议新开一个普通会话，或者在插件里关掉语音
模式后继续聊。同一条会话里从语音切到打字，并不会自动切回普通回答风格。

## 识别后端

按顺序尝试，失败自动往下一档退：

1. **外接接口**（设置里填了 URL 才启用）——OpenAI 兼容 `POST {url}`，
   multipart 字段 `file` + `model`，返回 `{"text": "..."}`。
   适用：OpenAI、Groq、硅基流动、Azure OpenAI、自建网关。
2. **本地 Whisper 桥** —— `http://127.0.0.1:8789/v1/audio/transcriptions`（可选）
3. **DSH 自带 SenseVoice** —— 默认，无需任何配置

## 合成后端

1. **外接接口**（设置里填了 URL 才启用）——OpenAI 兼容 `POST {url}`，
   JSON `{model, input, voice}`，返回音频二进制。
   适用：OpenAI、硅基流动、Azure OpenAI 等。
2. **内置 Edge TTS** —— 插件进程内用 `ws` 直连 Edge TTS WebSocket，内置常用音色
   （另可从音色库自动生成语言/音色列表），不需要任何外部进程
3. 外接 TTS 桥（如果本机跑着）

外接配置保存在 `~/.dsh/voice-tutor-config.json`。

ElevenLabs、Google Cloud TTS 这类请求体结构不同，需要改 `index.js` 里的 `ttsExternal()`。

## 纠错

收到识别文本后用 DSH 自己的模型修一遍：只改错字、漏字、明显的大小写/标点，
不改措辞、不扩写。含 6 位以上连续数字的句子整句跳过（避免改掉号码、金额、编号）。
纠错和 2 秒窗口并行跑，不额外增加等待。

## 音频格式

浏览器端用 `decodeAudioData` 解码录音，重采样到 16k、转成 16-bit PCM WAV 后上传，
**不需要 ffmpeg**。旧客户端若送 webm，且本机有 ffmpeg，宿主会自动转换（兼容路径）。

## 语音包

- 内置 13 个 Edge 音色（中/英/日/韩/法/德/西/意/葡/俄）
- `voice: "auto"` 时按文本主语言选音色
- 日语回复的汉字注音括号（`写真（しゃしん）`）在朗读前被剥掉，不会念两遍

## 本地 Whisper 更新检查

宿主侧逻辑在 `whisper-update.mjs`，只用 Node 内置能力，不新增依赖。

检查两件事：

1. **faster-whisper 包**：`GET https://pypi.org/pypi/faster-whisper/json` 取 `info.version`，
   与桥 venv 里实际安装的版本比较。安装版本优先用 venv python 跑
   `import faster_whisper;print(faster_whisper.__version__)`；失败时依次退回读
   `site-packages/faster_whisper/__init__.py`、`faster_whisper-*.dist-info` 目录名；全部失败
   报「未知」，不会因此报错。
2. **模型 revision**：`GET https://huggingface.co/api/models/<repo>?blobs=true` 取 `sha`
   （顺便汇总 `siblings.size` 作为模型体积），与本地 HF 缓存 `refs/main` 比较。缓存根目录按
   `HF_HUB_CACHE` → `HUGGINGFACE_HUB_CACHE` → `HF_HOME/hub` → `~/.cache/huggingface/hub` 的
   顺序解析；仓库名可用 `ASR_MODEL_REPO` 指定，否则由 `ASR_MODEL`（默认 `large-v3-turbo`）
   映射，和 `server.py` 对齐。

所有网络请求 8 秒超时，检查本身在 8 秒左右完成；离线或接口出错时只把错误放进 `errors` 数组，
不影响语音。结果写入 `~/.dsh/voice-tutor-config.json` 的 `whisperUpdate`：
`{ enabled, intervalHours, lastCheckAt, lastResult }`。宿主 `apply()` 后延迟 40 秒做首次检查，
之后按间隔用 `setTimeout` 链式调度；保存设置会重新调度。

更新动作（只有用户点按钮并二次确认后才执行）：

- **faster-whisper**：`<venv python> -m pip install -U faster-whisper`；成功后重启桥并等
  `/health` 就绪。起不来时尝试 `pip install faster-whisper==<旧版本>` 再重启，失败信息里会
  写清回滚结果。
- **模型**：用 `huggingface_hub.snapshot_download(repo_id, revision, cache_dir)` 下载到原缓存
  （旧 snapshot 不删），stdout 里的 `PROGRESS` 行转成百分比；完成后确认 `refs/main` 已指向
  新 revision，再重启桥。起不来时把 `refs/main` 写回旧 revision 并重启。

重启桥只处理监听 `127.0.0.1:8789` 的进程：先用 `Get-NetTCPConnection`（Windows）或
`lsof`（macOS/Linux）找 PID，再读命令行确认包含 `server.py`，否则拒绝操作、绝不误杀。结束
监听进程后用同样的命令行拉起新进程，并用一小段静音 WAV 做热身——桥是懒加载模型的，
`/health.ok` 只有在模型真正加载后才为 true，热身能让更新后的健康检查有意义。

## 日志与排查

- 日志：`~/.dsh/voice-tutor.log`（超过 2 MB 自动轮转为 `.log.1`）
- 最近一条消息的输入方式：`~/.dsh/voice-tutor-last-input.json`

| 现象 | 原因 |
|---|---|
| 识别为空 | 声音太小/录音太短；日志里 `stt-ok text=` 为空 |
| 冒出 "You" 之类 | Whisper 静音幻觉，已被过滤 |
| 没念出来 | 打字输入（设计如此）、语音模式未开、合成失败（看 `tts-local-fail`） |
| 念到一半停 | 打断逻辑判定你开口了；阈值见 `client.js` 的 `BARGE_MIN_RMS` |
| 重复发送 | 开了两个窗口；宿主按协议版本与会话去重 |

## 已知限制

- 日语纯汉字短句（如「東京駅」）auto 模式可能判成中文
- 只有 Edge TTS；接其它厂商需按协议改请求体
- 宿主代码改动必须重启 DSH（Node 模块缓存），客户端代码热更
- 转写准确率取决于后端：Whisper large-v3-turbo ≫ SenseVoice-Small
- 模型更新要重新下载约 1.5 GB（large-v3-turbo），期间识别会短暂中断；下载失败不会删旧缓存
- 自动更新桥依赖默认端口 8789 与 `server.py` 布局；换端口/换路径时用环境变量指定
- 更新 `faster-whisper` 可能连带升级 `ctranslate2` 等依赖；回滚只回滚包版本，不保证依赖树完全还原
