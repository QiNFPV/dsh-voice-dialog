# 详细说明

README 只讲怎么用；这里讲实现细节、外接接口和排查。

## 工作流程

```
麦克风(VAD) → MediaRecorder → decodeAudioData → 16k WAV
        → POST /voice-tutor/stt
        → Whisper / 外接接口 / DSH 自带 SenseVoice
        → 文字进输入框（2 秒窗口）→ 自动或手动发送
        → 宿主监听 assistant/message → 合成语音排队
        → 前端轮询取音频播放 → 期间可被打断
```

宿主路由：`/voice-tutor/stt`、`/voice-tutor/correct`、`/voice-tutor/arm`、`/voice-tutor/audio`、
`/voice-tutor/voices`、`/voice-tutor/config`、`/voice-tutor/debug`。

## 识别后端

按顺序尝试，失败自动往下一档退：

1. **外接接口**（设置里填了 URL 才启用）——OpenAI 兼容 `POST {url}`，
   multipart 字段 `file` + `model`，返回 `{"text": "..."}`。
   适用：OpenAI、Groq、硅基流动、Azure OpenAI、自建网关。
2. **本地 Whisper 桥** —— `http://127.0.0.1:8789/v1/audio/transcriptions`（可选）
3. **DSH 自带 SenseVoice** —— 默认，无需任何配置

## 合成后端

1. **外接接口**（设置里填了 URL 才启用）——OpenAI 兼容 `POST {url}`，
   JSON `{model, input, voice}`，返回音频二进制。
   适用：OpenAI、硅基流动、Azure OpenAI 等。
2. **内置 Edge TTS** —— 插件进程内直接调 `msedge-tts`，自带 13 个常用音色，
   不需要任何外部进程
3. 外接 TTS 桥（如果本机跑着）

外接配置保存在 `~/.dsh/voice-tutor-config.json`。

ElevenLabs、Google Cloud TTS 这类请求体结构不同，需要改 `index.js` 里的 `ttsExternal()`。

## 纠错

收到识别文本后用 DSH 自己的模型修一遍：只改错字、漏字、明显的大小写/标点，
不改措辞、不扩写。含 6 位以上连续数字的句子整句跳过（避免改掉号码、金额、编号）。
纠错和 2 秒窗口并行跑，不额外增加等待。

## 音频格式

浏览器端用 `decodeAudioData` 解码录音，重采样到 16k、转成 16-bit PCM WAV 后上传，
**不需要 ffmpeg**。旧客户端若送 webm，且本机有 ffmpeg，宿主会自动转换（兼容路径）。

## 语音包

- 内置 13 个 Edge 音色（中/英/日/韩/法/德/西/意/葡/俄）
- `voice: "auto"` 时按文本主语言选音色
- 日语回复的汉字注音括号（`写真（しゃしん）`）在朗读前被剥掉，不会念两遍

## 日志与排查

- 日志：`~/.dsh/voice-tutor.log`（超过 2 MB 自动轮转为 `.log.1`）
- 最近一条消息的输入方式：`~/.dsh/voice-tutor-last-input.json`

| 现象 | 原因 |
|---|---|
| 识别为空 | 声音太小/录音太短；日志里 `stt-ok text=` 为空 |
| 冒出 "You" 之类 | Whisper 静音幻觉，已被过滤 |
| 没念出来 | 打字输入（设计如此）、语音模式未开、合成失败（看 `tts-local-fail`） |
| 念到一半停 | 打断逻辑判定你开口了；阈值见 `client.js` 的 `BARGE_MIN_RMS` |
| 重复发送 | 开了两个窗口；宿主按协议版本与会话去重 |

## 已知限制

- 日语纯汉字短句（如「東京駅」）auto 模式可能判成中文
- 只有 Edge TTS；接其它厂商需按协议改请求体
- 宿主代码改动必须重启 DSH（Node 模块缓存），客户端代码热更
- 转写准确率取决于后端：Whisper large-v3-turbo ≫ SenseVoice-Small
